# 参数执行与任务快照规则

## 创建与填写

全部用户配置集中在 [config/extend.md](../config/extend.md)：JSON 仅保存手动默认值，表格列出完整参数说明与选项，不重复维护默认列。新任务由 `task_parameters.py` 生成五列表格，将 JSON 默认值映射为编号和选项说明；保留页首任务名称、专业领域及原参数顺序。配置文件不填写任务专属答案，生成的任务表不附全局配置说明。

本文件定义模板的使用规则。执行时读取表内参数定义、默认快照和答案；页首身份信息可补充身份答案并参与冲突检查。标题、技能名、展示版本及其他表外文字不是填写、审核或阶段执行的依据，删除这些说明不应改变有效参数的执行结果。规则版本从技能配置写入内部任务状态；历史表按实际选项含义及已有状态迁移，不能以缺少页首标记认定用户未填写。

首次使用按 [default-settings.md](default-settings.md) 在会话说明当前默认并提供 `config/extend.md` 的可编辑链接。长期调整只修改 JSON `defaults`。本次任务差异填写生成表的第四列，不回写成全局默认。没有调整要求就继续，不增加首次设置表或强制确认。

按 [user-interaction.md](user-interaction.md) 分工：批量参数主要由用户填文件，领域、起点澄清和方案确认优先通过允许的内置输入工具；工具或会话答案回填本表，用户不必重复手工填写。没有合适工具时按宿主许可使用编号文本问题或文件与直接确认。合并同阶段独立问题，保留依赖顺序。

先实际读取输入，自动识别格式与内容阶段，不在用户表中设置输入材料参数。没有上传文件、粘贴正文或可读取路径时提醒上传。系统记录实际输入路径与哈希，不能以参数校验通过代替输入已提供。

附件使用实际可读取文件；粘贴正文先原样留存为内部输入文件，再绑定路径与哈希。识别出的格式、材料阶段及来源记录在内部工作资料，不要求用户增加表格行。续接任务仍核对输入快照及起点要求的正文、方案或图片。

任务名称和专业领域一起询问，同时展示实际已有的完整领域选项，将明确回答同步到页首和表内第四列。任务名称用自由文本；领域可接受编号、显示名称或field_id并映射为本表编号。已明确答案不重复问，建议不当作答案。用户只填页首时程序也能读取；页首与表内冲突时集中澄清，不静默覆盖。

领域选项只列当前具有完整三个配置文件且标为ready的领域，不保留新增、自动识别或跨领域的占位编号。按本表选项的field_id解析领域，不用固定编号推测用途。新表按实际目录更新，已有填写文档的编号和field_id映射保持稳定。确需新领域时先在会话明确范围并建立配置，再出新表。名称与领域无跨任务默认，开始专业正文前必须加载所选配置。

表格固定五列：

| 参数名称 | 必选/可选 | 当前默认值 | 用户选择 | 参数意义及可选项 |
|---|---|---|---|---|

- 第二列使用“用户回答后回填”“用户选填”“条件选填”；名称和领域仍需有明确答案。条件触发的项目必须具备可用值。暂不适用的项目无需用户填写，不删除或重排选项。
- 第五列先说明用途，再列编号选项。每个选项用 `<br>` 独立换行，英文标识后附中文解释。保持模板编号，不因默认值、推荐、适用性或工具显示顺序重排；不兼容项可注明不可选。
- 第三列显示“编号.选项”默认值，没有默认则留空。生成后的默认列是本任务快照，不被全局配置静默覆盖；手动修改全局默认后只在生成新表时映射展示，已填写文件不追溯更新。
- 第四列普通选择填编号，任务名称填确认文本。用户选填项空白沿用展示默认，不计入明确回答；适用但无默认的项目集中询问，不猜测。页首身份留空时必须从表内或明确会话回填。
- 自定义选项仍填编号；实际参考文件、水印文字、配色、目录、数量及预算由会话或附件收集，转为任务内部 `_work/supplements.json`。预算含币种，不将专属路径或金额存入偏好。
- 状态、执行值、来源、条件、确认范围及任务 ID 写进 `imgs/settings.md`；用户表只保留五列。采用工作记录后，用户表仍是本次明确选择的依据，不创建第二套互相冲突的填写表。

生成填写文件可运行：

```text
python scripts/task_parameters.py --out <供用户填写的MD> [--task-name <已确认名称>] [--field <已确认field_id>] [--config <显式配置路径>]
```

输出不覆盖已有文件。名称和领域未确认时保留空白，确认后回填。全局自定义数量、压缩等默认值随任务表保存补充快照；校验时仅在第四列空白且默认列未变时使用，明确补充值优先。用户改填自定义选项时重新收集本次值，不继承另一份补充值。用户填写完毕重新读取实际文件，校验所有适用参数；提供文件和打开文件不是用户已填写完成的证据。

填写后留存：

```text
python scripts/task_parameters.py --filled <用户填写完毕的MD> --output-root <输出父目录> --timezone Asia/Shanghai --input <实际材料文件> [--input <其他材料>] [--supplements <内部补充JSON>] [--scope <范围>]
python scripts/task_parameters.py --filled <用户填写完毕的MD> --state <已有任务/_work/task.json> [--input <实际材料文件>] [--scope <范围>]
```

校验通过才创建新任务；已有任务沿用原目录、时间和UUID。将填写文件原字节保存为 `<任务名称>_参数.md`，绑定输入与参数哈希，不删除用户原件、不覆盖不同内容的同名文件。已经在任务目录原位填写时直接绑定该文件。原文件和已有任务名称冲突必须澄清；归档只完成参数准备，不会生成正文或图片。正式生成前仍需实际阅读输入和核对授权范围。单篇规则见 [longform-variants.md](longform-variants.md)。

## 本次任务起点

本次任务起点为用户选填，全局默认在 `extend.md` 的 `defaults.本次任务起点`，出厂为1（原始内容）；JSON 可写完整选项说明或名称，也兼容数字1至5。生成任务表时统一映射为编号选项；用户选择列仍填编号。留空按任务表展示默认执行，不要求单独确认。已有明确选择或任务快照优先，不另列自动判断或通用续接。输入识别不等于起点选择；规则版本保存到内部状态，不添加用户页首字段。迁移旧表先核对选项含义，面向用户只说明从哪里开始。

1. **原始内容**：从整理或转换原始材料开始。
2. **已转换或无需转换的内容**：正文已准备好，从配图分析开始。
3. **配图方案**：已有方案，从检查或完善方案开始。
4. **生图**：方案已确定，从生成图片开始。
5. **正文插图+发布内容生成**：已有正文和图片，从插图及生成成品开始。

起点1至4最终接续5；图片审核0时4经技能自检通过后直接进入5，1时先等待图组确认。第三项处理方案，第四项执行生图，第五项使用已有图片组装成品。明确只做某阶段时范围优先；材料已成文不自动授权改写。“原文不改只配图”映射2，“优化／转换”映射1，“完善已有方案”映射3，“确定方案后生图”映射4，“已有正文和图片生成成品”映射5。参数缺失、事实冲突或前置材料不足时集中澄清，起点编号不是资料齐全或审核通过的证据。

起点 2 保留原有标题、文字、标点、段落顺序及引用链接，审核稿只加规划块，配图版只加图片和独立图题；移除新增块后应恢复输入正文。从 Word、PDF 提取时保留实际可取得的正文，不承诺不同格式的字节或版面完全一致。技术或事实问题在会话说明，影响图义时先确认处理，不静默修改，也不画图强化错误结论。

历史任务不静默重新解释旧编号。旧1、2、3按原材料和范围对应新1、2、3；四起点版本的旧4若从确定方案后生图对应新4，若只复用已有图生成成品对应新5。更早的旧5通用续接、旧6自动判断按实际阶段映射，不能把旧5直接解释成新5；旧7优化文章映射新1并保留体裁。迁移先核对实际选项文字及确认记录，不改输入或扩大范围。旧任务新增图片审核开关时保留原审核约定；未约定人工图片审核的任务记录历史沿用0，不因默认变化改变已有审核约定，也不伪装成明确回答。

用户明确只做某阶段时范围优先。五个平台由共同内容和图片并列生成。未另指定终点时接续剩余流程：方案审核1时生图前等方案确认；图片审核1时技能自检通过后等图组确认；对应开关0时分别跳过用户确认，技能自检始终执行。

## 条件校验

任务开始先识别材料，采用已填起点或默认1；可继续读取、分析不依赖缺失参数的内容。在讲义和视觉分析完成后记录适用条件，展示全部适用作图选项。预设与独立类型、风格、配色均解析有效值；选填留空采用展示默认，不要求逐项再次确认。明确独立值覆盖预设，不把覆盖视为错误。

没有参考图时参考用途不适用；不加水印时文字和位置不适用；PNG 时压缩不适用；已有图片处理仅在目标范围实际有图时适用。自定义必需信息、无效编号或互斥组合未解决时，不执行相应阶段。相同任务的已有明确选择不重复收集；后续修改更新本表及工作记录，实质改变方案时重新确认变更。

按本任务表的编号映射为语义值，例如质量编号 `3` 映射到 `"medium"`、图片信息展示编号 `2` 映射到 `false`，作为本任务的执行值；不能把语义值误当编号再次解析。任务答案不提交给全局配置程序、不回写默认。五个平台开关是本次范围，0不输出的项目跳过。续接旧表时保留所有已填值，追加缺少的平台开关并标明兼容来源；旧任务明确限定范围时不自动扩大。旧参数表里的已移除选项仅保留原文，不参与执行。

用户明确免于填写或指定全部有效参数时仍生成参数文档并记录实际采用值和指令来源，不把推断值填为用户回答。审核开关为1时参数选择不能代替方案确认，为0时校验后记录方案和实际图数并直接执行。

## 0/1 流程开关

“是否使用 image-gen”默认1使用，仅需要实际生图时适用；0表示不使用该技能，由用户自行选择生图方式。只有这两项，不收集通用自定义API配置，使用时依赖实际可用的 image-gen 并采用其提供的渠道，不用时不依赖它，其专用模型、质量等固定参数不适用。两种方式都保留配图设计、提示词、数量预算、专业自检、审核与正文插图。旧表缺行记录默认1及来源，不迁移旧密钥；具体交接见 [image-backend.md](image-backend.md)。

`model`、`resolution`、`quality`、`background`、`output_format`、`output_compression`、`moderation`、`show_info` 均标为“条件选填”。仅在 `use_image_gen=true` 且当前流程需要生图时解析，留空沿用任务默认快照；无可用值或选项冲突时再补充。`output_compression` 还需输出 JPEG 或 WebP。不使用 image-gen、仅处理正文或从起点5直接插图发布时，忽略这些参数的答案，不要求补填。任务表保留全部参数行和选项，便于本次切换服务选择；比例、参考图、变体数量等共用参数继续按原有配图规则处理。

完整配图正文另有“是否输出content”可选开关，默认1输出，0不输出。开启后导出HTML、EPUB、PDF到publish/content/任务名称，不依据平台稿改写；参数校验、状态、发布证据与成品包都包含这三份。历史表缺此行时沿用0，本次明确增加才追加。`scope=content`仍指仅基础正文，不触发阅读版导出；只输出阅读版需full或publish范围并关闭五个平台。

按 [workflow-switches.md](workflow-switches.md) 处理审核及平台范围。方案审核出厂默认0不需要，图片审核出厂默认0不需要，五个平台独立出厂默认1输出；可选开关留空沿用已展示默认，0是有效答案。旧表平台1生成、2不生成迁移为新1输出、0不输出，保留旧范围。关闭的平台不生成目录或成品，所有平台关闭时只执行所请求的内容与配图，不强制发布封面。
