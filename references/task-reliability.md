# 输入、执行和交付可靠性

## 固定执行约束

新任务先按 [reliability-tools.md](reliability-tools.md) 做一次环境预检，再按阶段使用数值回查、方案v2校验和执行参数快照。执行工具不能代替专业审校；仅复用已有成果时不新增生图请求。

1. 实际读取输入后，用task_state.py的inputs事件绑定实际输入文件路径和SHA256。参数校验通过后，用parameters事件绑定校验结果及本次参数表快照；表外补充、领域三个文件及方案设置也纳入相应阶段证据。重新绑定时若输入或领域哈希变化，必须接受程序自动失效下游阶段的结果。程序校验通过不能代替实际读取或专业审校。
2. 根据本次scope、五种起点、平台开关建立交付清单；parameters事件将verify_task.py中expected_files的结果保存到task.json的deliverable_manifest，不凭记忆套用旧目录示例。三个长平台全开是3份长文，按内容决定篇幅，两个短平台各1份。已有合格前置成果可以导入并留证据，不伪造已执行阶段。
3. 每阶段开始记录running；通过后记录实际文件的路径与SHA256，失败记录failed，等明确答案或审核记录waiting。task.json的status为complete之前，只能称为进行中、待确认或部分成果。不要把文件夹存在、请求成功或内部草稿完成当作成品交付。
4. passed证据必须绑定当前文件。图片逐张实际检查文字、专业关系、构图和正文映射；技术图还要逐条核对图片语义契约中的节点、方向边和禁用关系。新图修改后复检，再更新证据。正式配图正文、平台草稿及导出分别检查，不能沿用修改前的结论。
5. 输出发布文件后完成适用检查：DOCX正文与草稿一致、图片内嵌及实际渲染查看；HTML正文与草稿一致、桌面/手机排版、实际复制按钮载荷和失败回退；短平台标题/文案/标签及图片选择一致。用publish阶段证据绑定所有成品、内部草稿、导出记录及实际QA记录。QA记录须对应本次成品，不填写未做检查的通过结果。
6. 执行 `python scripts/verify_task.py --state <_work/task.json> --complete`。缺文件、过期快照、未通过阶段、错误图序/图片字节、断链或两短平台图组不同均不能完成。程序将结果保存到_work/qa/completion.json；退出码0才表示本次文件和证据验收通过。专业审校和目标平台粘贴仍是独立事实，程序不能证明模型知识永远正确。

阶段必需文件按当前scope及起点检查。content必须绑定本任务内容MD，plan绑定审核稿，illustrated绑定正式配图正文；full起点1／2不能缺content记录。阶段schema2保存输入／上游依赖与领域，变更上游重新记录会使下游pending。不要用无关QA代替正文。长平台实时核对当前成品与允许排版变换后的草稿，不单凭旧text_verified标记；短文案拒绝嵌图、链接路径和制作标记。历史下游失败不阻断本次无依赖的content范围。

验收只在一次调用内缓存相同路径与文件状态的哈希，结束时重查文件状态；提交complete再次验证，不跨调用复用旧哈希。报告elapsed_seconds用于本机定位耗时，不代表全流程生成速度。

## 续接与变更

content开关开启时，交付清单另含完整配图正文的HTML、EPUB、PDF三份，不依据平台稿改写。按 [content-documents.md](content-documents.md) 实际检查目录、书签、内嵌图片及版面；publish证据绑定三份文件、原配图MD、导出记录与本次QA。历史表没有此开关时不新增；关闭时保留已有成果但不纳入本次成品包。

续接先读取同一task_id、参数与输入快照、阶段证据和completion.json。当前哈希一致且实际审校通过的资产复用；缺失或失效的成果及依赖它的下游成果重新检查或补做。沿用原任务目录、文件名和图片，不因续接创建新时间目录或重复学习偏好。

参数变更先重新校验并更新快照，重新推导交付清单。只改平台或篇幅时复用合格共同正文及图片，仅处理受影响的发布成果；输入、领域、方案或图片变化时重新核对实际影响，失效的下游阶段改为pending，不沿用旧审校。不要将重建工作记录当作重新生图的授权。

生图前检查已有成功结果和请求记录，服务结果已成功时复用。请求发送后结果未知，不盲目再发付费请求；先查询已有状态，无法确定则据实说明。重试与修复次数遵守原预算及既定上限，不为了达到“complete”无限重试。

历史任务缺少快照时，重新实际读取输入并校验当前参数后补记，明确这是当前时点快照，不能声称能证明历史输入未变。用户删除_work后保留成品，但自动续接证据已丢失，须重新审校。验收报告可识别漏项，不能恢复被删的历史记录。

## 交付

最终消息按实际验收结果给出交付范围、数量和成果链接。失败或等待时列明具体缺口和续接位置，不宣称完整。技术检查报告留在_work，不混入第一作者正文。任务完成后更新任何阶段或参数会清除旧完成标记；再次交付须重新验收。
