# 配图方案审核与输出开关

本次任务起点和本文件中的全部流程开关，其全局默认均在 `config/extend.md` 的 JSON 配置，生成新表时写入第三列。下列数字仅描述出厂默认及无快照时的兼容回退，不能覆盖已配置的任务快照。起点优先采用明确填写，其次采用有效任务默认快照，无快照则用1；缺少起点行或旧编号语义不明时仍先迁移。

每个新任务参数表必须有“是否需要配图方案审核”“是否需要图片审核”及每个平台的“是否输出”独立行。它们是流程开关，不是作图服务 API 参数。所有参数的长期默认均只在统一配置中手动修改，任务选择不回写配置。

| 参数 | 出厂默认及兼容回退 | 允许填写 |
|---|---|---|
| 是否使用 image-gen | 1.使用（流程默认） | 1.使用 / 0.不使用 |
| 是否需要配图方案审核 | 0.不需要（流程默认） | 1.需要 / 0.不需要 |
| 是否需要图片审核 | 0.不需要（流程默认） | 1.需要 / 0.不需要 |
| 是否输出CSDN | 1.输出（流程默认） | 1.输出 / 0.不输出 |
| 是否输出抖音 | 1.输出（流程默认） | 1.输出 / 0.不输出 |
| 是否输出微信公众号 | 1.输出（流程默认） | 1.输出 / 0.不输出 |
| 是否输出小红书 | 1.输出（流程默认） | 1.输出 / 0.不输出 |
| 是否输出知乎 | 1.输出（流程默认） | 1.输出 / 0.不输出 |
| 是否输出content | 1.输出（流程默认） | 1.输出 / 0.不输出 |

这些行均为用户可选。第四列明确填写0或1时优先采用；留空时沿用本任务第三列已展示的默认快照，并记录来源，不假装成用户明确回答。仅无快照的新任务使用流程默认。不能使用真值判断来检测填写：`0` 是有效答案，不是缺失值。用户明确限定只做某阶段或某些平台时，范围优先，关闭不在范围内的输出，不被默认1覆盖。

“是否使用 image-gen”仅在本次需要生图时适用，1时调用该技能及其提供的渠道；0时不检查或调用它，不要求兼容其API，保留全部设计、自检和审核。历史表缺行记默认1及来源，不迁移旧凭据、不自动重生已有图片。`route.use_image_gen`记录选择；`stages.call_image_gen`只在实际生图范围且选择1时为真。`generate_images`仍表示本次有图片获取阶段，不等于调用了 image-gen；未指定其他工具且没有图片时等待交接，不报完成。

解析保留任务第三列默认快照，来源记为“任务默认快照”；仅无快照的新任务使用当前流程默认。新任务内部版本为parameter_schema_version: 4、starting_point_schema_version: 2，不在公开模板新增版本说明字段。旧起点确认语义后迁移。新表每长平台一篇；历史分档表仅用于旧任务续接。规则见 [longform-variants.md](longform-variants.md) 和 [task-state.md](task-state.md)。

填写后使用 `python scripts/workflow_switches.py --parameters <任务参数文件>` 解析五种起点与独立开关。起点3处理已有方案，4执行生图，5使用已有图进行正文插图和发布生成。输出阶段标记及两项用户确认要求不是确认已通过的证据；技能必须核对当前方案或图组的确认记录。起点5不生图，不要求重新审核生图方案，但图片审核仍适用。程序仅解析，不执行生图或创建目录；缺少必填或兼容性有误时集中澄清。旧表迁移先按实际选项文字核对含义，不能直接按旧数字执行。

## 审核开关的流程

- `1.需要`：完成适用参数校验，生成 `<任务名称>_内容_配图审核稿.md`，交付候选及实际图数、封面、变体和预计请求数，等待用户对当前方案确认。修改请求只授权改稿，不视为批准生成；修订后再次确认。
- `0.不需要`：仍分析结构、规划封面与插图，生成同名规划稿及 `imgs/outline.md`，记录实际图数、参数、变体、预计请求数和约束，并在进度中告知，然后直接准备提示词和生成，不额外提出审核确认问题。稿件在此分支是方案留档，不是等待填写材料。
- 不需要审核仅跳过用户对配图方案的审阅；必填参数校验、兼容性检查、预算与数量限制、专业审校、逐张看图及正文一致性检查仍执行。仅要求修改技能、仅整理内容或仅检查配置，不因默认0而启动生图。
- 配图不在本次范围或使用现有图组且无需新图时，审核行标为不适用；不为开关创建多余图片任务。默认0适用于用户已经要求执行完整内容生产或配图的本次范围，不扩展为任意收费测试、自动重试或超预算任务。
- 起点3“配图方案”检查、补全或调整现有方案，起点4“生图”执行确定方案；两者方案审核1且无当前确认时先等待，0时校验留档后执行。起点5“正文插图+发布内容生成”不生图，方案审核不适用。选择起点不等于批准方案或图组。
- 旧任务的历史审核承诺和已确认范围沿用，不能因新默认自动跳过等待。用户明确要求当前任务免审时才调整。新增或实质改变已确定方案的范围时，审核为1则再确认，为0则更新记录并告知，在原授权和限制内执行。

## 图片自主检查

无论方案审核选择0还是1，技能都必须逐张实际查看图片，检查乱码及文字准确性、专业错误、构图可读性、与正文和插入位置的对应关系。发现问题后自主修正提示词，在已约定请求数和费用限制内每张最多生成一次技术修正版，并实际看图复检，不要求用户承担检查或逐次批准常规修复。不合格图排除，关键缺口停止受影响阶段并据实说明；不得把“用户免审”解释成免于图片检查。记录问题与修正结果于工作资源，不混入公开正文；具体检查与限制见 [illustration-workflow.md](illustration-workflow.md)。

## 用户图片审核

“是否需要图片审核”独立于方案审核，新任务默认0不需要，1需要。无论0还是1，技能自检的范围、检查深度、专业依据、修正及复检标准完全一致，不能因关闭用户审核减少检查。此开关只决定合格图组交付后是否等待用户确认。

- `1.需要`：展示合格图组、编号及对应正文位置，记录文件版本和哈希，停止等待当前图组确认；未确认前不生成正式配图正文与平台稿。用户可提出文字、专业内容、构图或对应关系的修改，修改请求不是批准。按明确反馈及既定预算处理，复检后再确认；超出修复次数或原范围时先明确新增范围，不无限收费修改。
- `0.不需要`：记录技能自检通过的资产，直接进入正文插图与发布生成，即4自检通过后接续5，不追加用户审图问题。
- 起点5使用已有图组时仍实际核对图片；图片审核1且有当前图组确认记录则复用，不重复等待，缺记录则先交付图片确认。文件或图义实质改变后旧确认失效。用户批准不能覆盖技能发现的关键技术错误。
- 无图片的明确任务此开关不适用。旧任务缺此行时解析为历史沿用0，并核对原确认约定；不能以新默认覆盖旧任务已明确的审核约定。已有人工审图约定则补入1及来源。

## 平台输出规则

每个平台单独解析：1输出，0不输出。关闭时不写对应稿件、不导出、不复制图片、不创建空平台目录、不放入成品包；已有平台成果不删除。全部为0时只交付本次范围要求的内容与配图；正文配图任务不强制生成发布封面。两个短平台都开启时共用同一精选图组和顺序；只开启一个时只交付该平台。

content是与五个平台并列的完整正文阅读输出，使用“是否输出content”独立开关，不依据平台稿改写。1时将当前配图MD导出为HTML、EPUB、PDF，放`publish/content/<任务名称>/`；0时不导出、不创建目录、不纳入本次成品包，已有文件保留。全部输出为0包括content；只输出content时不强制新增发布封面、不重新生图。用户说“只输出某平台”时也关闭content，用户说“只输出content”时关闭五个平台。

历史参数表没有content行时解析为0，来源为“历史表未设置，保留原输出范围”。本次明确要求新增content时追加该行、填写1并重新校验参数与交付清单；不重做合格前置成果。新表展示默认1，留空沿用默认快照，明确0优先。解析结果的`selected_platforms`列出五个平台中已开启的项目，`selected_outputs`另包含content；`all_outputs_disabled`核对六项开关。

## 历史表迁移

旧表“是否需要配图审核”仅为新“是否需要配图方案审核”的历史名称，沿用原0/1答案；两行同时存在时先合并确认，不静默选一行。旧表平台行的名称如“知乎文章”“抖音文案”等，1生成仍对应新1输出，**旧2不生成必须迁移为新0不输出**。根据旧表实际选项含义转换，不将2直接接受为新值，也不将历史默认或空白写成明确回答。迁移时保留已有答案、原范围与来源，不改变其他参数编号。新开关只接受0或1，空白按默认处理，其他值集中请求更正。
