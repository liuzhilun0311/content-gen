# 可靠性工具与内部证据

本文件定义内容生产时的环境检查、参数校验及内部证据。保留输入原件和已有成果；私有配置只供运行程序读取，不混入正文、提示词或交付文件。

## 运行前

每次批次先运行一次：

```text
python scripts/runtime_preflight.py --profile <content|plan|images|publish|full> --workspace <存在的工作目录>
```

从结果读取实际Python、Node、marked、浏览器和可用渲染器路径。在本技能的 `config/.env` 中用 `SANBAO_NODE`、`SANBAO_MARKED`、`SANBAO_PLAYWRIGHT`、`SANBAO_BROWSER` 配置本机工具路径；缺少文件时可从 `config/.env.example` 创建，不覆盖现有文件。含空格的路径可用引号包住。优先级为导出命令的明确参数、同名进程环境变量、`config/.env`、自动发现；环境变量为空时清除文件中对应值并自动发现。预检和导出共用该配置，`--node`、`--marked` 可省略；偏好仍单独放在 `config/extend.md`。预检实际运行marked及适用的浏览器启动；Word注册信息只证明可用候选，不代表DOCX已渲染。预检不调用生图服务、不验证API凭据。

## 内容与长平台草稿

```text
python scripts/review_material.py --source <原始TXT> --source <其他实际来源> --draft <正文或平台草稿MD>
```

将JSON保存到本任务 `_work/qa/`。每条数值保留原文、SHA256、行号、字符位置和上下文；中文数词、数量范围、百分之数值及公里、度电等常见单位都扫描，原始表达不自动转换。来源和成稿采用不同表述时可能产生提示，不能据此宣称数值错误。人工补充对应位置、单位换算、时间基准、采样方向、温度、倍率、截止条件及容量口径；未匹配项给出遗漏或等价表达理由。新增型号、标准、算法结论另记录一手出处、版本日期和适用条件。

扫描器不是完整自然语言理解工具；隐含数值、没有单位的数字和范围边界仍需人工阅读。按longform-variants.md建立共同知识台账，逐平台记录必讲单元的覆盖位置和适用条件。历史统计、计划和预测注明原材料时间与性质，标题和尾段范围不一致需实际核对。长材料连续分段阅读并记录覆盖，不能用首尾抽样代替完整阅读。数字一致不能代替知识完整性。

篇幅用 `markdown_contract.py` 的统一AST计算，排除标题、图注、参考文献章节、代码和独立公式；正文内带变量表达的说明仍计入。三个长平台各一篇，正文、简介和摘要均无字数目标。计数仅保存在导出记录中作统计，不要求偏离理由，不因统计值阻断，也不自动删减或凑字。知识覆盖、来源条件和图文对应仍须实际审校。

## 配图方案和执行参数

按 [image-semantic-contract.md](image-semantic-contract.md) 保存 `_work/image-plan.json`，运行v2方案校验并保存结果：

```text
python scripts/validate_image_plan.py --plan <任务根目录/_work/image-plan.json>
```

仅“是否使用 image-gen”为1且本次需要生图时生成执行快照；为0时不运行此映射器、不检查 image-gen 配置，将所选方式的非敏感设置和实际图片映射绑定plan阶段证据。方案、提示词及专业检查不受开关影响。

```text
python scripts/effective_image_config.py --validation <本次参数校验JSON> [--aspect-ratio <逐图明确比例>]
```

配置结果保存 `_work/execution-config.json`；参数表、补充参数、校验JSON和执行配置都绑定plan阶段证据。逐图比例仅在参数选择“按各图内容安排”时提供；固定比例不能被逐图值覆盖。preset、type、style、palette、language和水印属于提示词配置，逐图落实并人工核对；references中的实际文件逐个传入后端。调度批次、图数和修复请求上限由调用者执行，不能把JSON中的上限字段当作后端已经控制费用。

```text
node <实际发现的image-gen根目录>/scripts/gpt-image2.mjs --execution-config <execution-config.json> --prompt <本图已校核提示词> --out-dir <本任务已选图片目录> --dry-run
```

dry-run只检查请求形态，不生图。正式执行沿用已授权预算和请求上限，去掉dry-run。`design`背景、服务默认格式／压缩／审核会明确清空任务级字段，避免私有环境默认偷偷覆盖；模型、质量、尺寸、比例和候选数来自同一快照。调用者不得再用矛盾的CLI参数覆盖该快照。服务URL、API凭据和网络重试设置仍从私有配置读取，不进入公开执行配置。

## 证据与缺陷

passed阶段必须绑定当前内容、审核稿或配图正文等本阶段实际文件。新阶段记录自动绑定上游文件和领域；正文／方案变化重新记录时下游失效，旧图片确认不得复用。表外补充和领域三个配置文件绑定适用阶段证据；领域文件修改后重做内容审校。仅变更平台表达或取消篇幅档位不用重生图，当前scope只验收适用阶段。full起点1／2必须有content通过记录。

长文验收重新抽取当前HTML／DOCX正文，按共享排版契约与草稿比对，同时检查摘要／标签和新记录的输入输出哈希；只刷新成品哈希不能掩盖正文漂移。历史没有排版变换记录的导出按历史原草稿核对；不自动改写历史QA。短平台只允许标题、文案、标签，禁止图片语法、素材路径和制作标记。

技术接线、方向、因果、单位及知识错误是阻断缺陷。文字白名单、乱码、构图等按现有四项图片检查记录；另在notes记 `technical`、`text`、`layout` 和具体原因，技术错误必须修正，风格问题不能冒充技术错误，也不能为了通过把真实错误降级。程序不自动识别图片中的箭头或承诺专业准确率。
