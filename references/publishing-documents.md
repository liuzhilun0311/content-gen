# 长平台文档与复制排版

知乎、微信公众号和 CSDN 成稿审校后读取本文件。知乎交付内嵌图片的 DOCX，公众号与 CSDN 交付富文本复制 HTML；三个平台都交付引用原图。格式转换不改写正文，不重新生图。

完整配图正文的content阅读版是独立输出，按 [content-documents.md](content-documents.md) 导出HTML、EPUB、PDF，不使用平台复制页，不依据平台稿改写。

## 交付格式

- 知乎：发布版 DOCX、同一总封面及正文引用的原图。发布目录不放 Markdown。
- 微信公众号：复制排版 HTML、同一总封面及正文引用的原图。发布目录不放 Markdown 或 DOCX。
- CSDN：复制排版 HTML、同一总封面及正文引用的原图。发布目录不放 Markdown 或 DOCX，内部草稿保存在 `_work/drafts/CSDN/`。
- 导出所用 Markdown 仅为内部草稿，保存在 `_work/drafts/知乎/` 或 `_work/drafts/微信公众号/`，不放进发布目录或默认成品包。参数表、审核稿、提示词及核验记录仍属于工作资料。
- 原图保留文件名及字节内容；名称碰撞且内容不同则停止，不覆盖。内部草稿的图片引用按草稿目录解析。
- 知乎 DOCX 图片必须真正内嵌，核对正文、图序、图片数量和原图哈希，不保留外部图片关系或本地路径文本。

## 图片与图注

按 [article-layout.md](article-layout.md) 将标题统一为任务名称，合格封面紧跟正文标题；图注及封面说明末尾不留中文或英文句号，正文标点不变。导出记录保存这些排版变更，验收时将其与内容改写区分。

- 常规图片默认保持原始比例、居中，桌面显示为正文可用宽度的85%，手机宽度不超过600px时显示为正文宽度的100%，利用正文左右边距留白。不拉伸、不裁切、不重新生图。用户另有要求时优先采用；横向流程与对比可用90%，简单概念与单对象可用70%～80%，字体可读性优先。
- DOCX图片同样居中，默认宽度为页面扣除左右页边距后可用宽度的85%，高度等比计算；不能按整张纸宽度设置图片尺寸。
- 每张内容图下方使用独立图注，格式为“图1 图片含义”，按本篇出现顺序从1编号；各平台各篇幅版本分别编号。封面不编号，有封面说明时也居中显示。文件名与工作方案的稳定资产编号保持不变。
- 图注说明图片表达的核心含义，可以补充图内标题未覆盖的关系；不机械重复图内标题，不写“图.图片含义”。图注居中、常规字体而非斜体、深灰、无首行缩进，HTML约14px（正文16px），DOCX约10pt（正文11pt）；长图注自然换行。图片与图注间距约8px，图注下方约24px。
- 成稿阶段先将图注作为普通Markdown段落写入配图正文或平台草稿，紧跟图片引用，不使用任意布局HTML。原文保留入口只添加独立图注，不改正文。导出按草稿的图注原文排版，不在导出时自动补造或改写说明；已有旧稿没有编号时，在获授权的成稿修订阶段处理。
- 桌面和手机核对所有图片居中、宽度、原始比例、图注字号与换行、图序与编号连续性、封面未编号；DOCX也检查图片宽度、图注居中与分页，尽量保持图片和图注同页。HTML手机自适应由预览样式实现，复制正文保留内联的85%默认宽度；目标编辑器是否保留响应式样式需要实际粘贴验证。

## 公众号复制页

页面提供四个独立区域及按钮：“复制标题”“复制简介”“复制标签”“复制正文”。简介准确概括本篇文章，不设字数目标；标签围绕实际主题，以空格分隔 `#标签`。不用截断首段替代简介，不编造亮点、效果或热点。

标题、简介、标签复制纯文字；正文复制渲染后的 `text/html` 与 `text/plain`。工具栏、简介、标签和重复的标题全部位于正文复制区域之外。不能把 HTML 源码或操作说明混入正文。复制失败时显示对应区域的失败状态并选中文字，不能假称已复制。

公众号正文约16px、行高约1.75、段后约18～20px，小标题约20px加粗。使用常见中文无衬线字体、深灰正文、黑色小标题、白底、零字距和无首行缩进，图片等比自适应；样式内联到实际段落、标题、图片和表格。用户指定品牌排版时优先采用。必要公式、引用及表格应保留。

页面内嵌图片供离线预览，原图同时随文件交付。本地复制成功不代表图片已上传或目标后台粘贴已验证。区分微信开放社区与公众号后台；无需登录、上传或自动发布即可完成文件交付。

## CSDN 复制页

沿用公众号复制页的富文本排版与离线图片方式，但仅有“复制标题”“复制正文”“复制文章摘要”三个按钮，不显示标签区。摘要直接依据本篇正文提炼，不设字数目标。标题和摘要复制纯文字，正文复制 `text/html` 与 `text/plain`，工具栏、重复标题及摘要都不混入正文复制区域。保留必要代码文本与缩进、公式、引用及表格。相同模板通过平台参数区分字段，公众号的四按钮规则不变。

## 执行与核验

写作、导出、验收共用 `scripts/markdown_contract.py` 的AST与排版文本契约；导出记录包含layout_changes、number_sections、source_sha256、output_sha256及text_metrics。字数只作统计，不要求篇幅偏离理由；按 [reliability-tools.md](reliability-tools.md) 保存知识覆盖和数值条件回查。DOCX图片等比限制在可用页高内，图片与图注相随，图注不强行绑定下段；仍须实际渲染检查分页。

新任务按 [longform-variants.md](longform-variants.md) 每平台单篇导出，目录为publish/平台，使用--task-root且不传--variant，文件名保持任务名称_平台_publish.后缀。草稿放_work/drafts/平台，报告放_work/export/平台英文ID.json。历史分档续接按原路径及--variant执行，不改动已保存成果。

支持普通段落、标题、表格、代码、引用、嵌套列表以及行内sup/sub/br；拒绝任意布局HTML或未支持标记，导出前集中预检查，不在导出失败后默默删知识。公式采用已校核的可读Unicode或sup/sub上下标，复杂LaTeX需先用可用的标准公式渲染器处理并检查，不能交给AI图像模型绘制。当前脚本不直接渲染LaTeX，遇到数学定界符在写成品前停止并说明；原稿保留，等价排版转换由技能核对，不假称目标平台会自动渲染。

使用 `scripts/export-publishing-documents.py`，从当前环境解析 Python、Node、`python-docx` 和 `marked`；有依赖加载器时优先使用返回路径。不读取生图密钥。

```text
python export-publishing-documents.py --source <内部草稿MD> --task-name <任务名称> --platform zhihu --output-dir <publish/知乎> --node <Node路径> --marked <marked模块路径>
python export-publishing-documents.py --source <内部草稿MD> --task-name <任务名称> --platform wechat --output-dir <publish/微信公众号> --summary <文章简介> --tags <空格分隔的标签> --node <Node路径> --marked <marked模块路径>
python export-publishing-documents.py --source <内部草稿MD> --task-name <任务名称> --platform csdn --output-dir <publish/CSDN> --summary <文章摘要> --node <Node路径> --marked <marked模块路径>
```

新任务追加`--task-root <任务根目录>`，不传--variant；各平台使用本篇简介或摘要及适用标签，共享已审校原图，无额外生图。

按 [task-naming.md](task-naming.md) 使用固定文件名 `任务名称_平台_publish.后缀`，执行时必须传入 `--task-name` 与平台发布目录。公众号和 CSDN 只写出 HTML，不写出 DOCX。同名成果存在时不追加后缀；明确整版重做才创建新时间目录。用户明确局部修订时沿用当前任务和受影响平台目录，保留必要历史后使用 `--replace`，不再确认已授权的修订。导出记录放 `_work/export/`，草稿放 `_work/drafts/`，检查中间文件按命名参考管理，不在根目录创建额外 QA 目录。简介、摘要与适用的标签必须基于实际正文写好后传入，不新增用户必填参数。依赖不可用时保留工作草稿和原图，说明交付缺口。

HTML直接内嵌PNG、JPEG或WebP原字节，不依赖系统媒体类型登记。DOCX优先使用PNG或JPEG；若选WebP，先以标准图像库无损转为PNG并核对尺寸、透明度和像素等价，保留原件及转换记录，再引用该核验副本。不得把未经核验的格式转换称为原字节一致，不重新请求AI生图来转换格式。

1. 知乎核验 DOCX 文字与草稿一致，图序和媒体哈希一致，图片关系均为内部关系；使用可用渲染器实际检查版面。无法渲染时说明范围。
2. 公众号在桌面和手机宽度检查所有图片加载、字号、间距和横向溢出；分别实测四个复制按钮及失败回退。核对简介和标签忠实于本篇文章，复制正文不含标题、简介、标签或工具栏，富文本样式内联，正文与草稿一致。
3. 成品包只包含各平台指定格式和原图，工作草稿不混入；不生成多余的公众号 DOCX。
   CSDN 同样核验手机与桌面宽度、图片原字节、正文与草稿一致及三个复制按钮；正文不含标题、摘要或工具栏，不显示标签按钮。
4. 未在目标编辑器测试时，只能报告本地排版与复制检查结果，不能承诺目标粘贴完全无需调整或图片上传成功。
