# 新领域三个文件的编写结构

本文件是编写结构，不是可直接使用的专业配置。依据实际材料写出内容后再保存到 `fields/field_<slug>/`，不能用下面的标题或描述代替专业规则。范围未确定时保留 `draft` 并澄清。

## expert-teaching.md

文件开头写 YAML 元数据：

```yaml
field_id: field_英文领域标识
display_name: 中文领域名称
version: 1
status: draft
```

正文包含：

- 领域范围：主要主题、关联主题、范围边界及明确不适用的用途。
- 目标读者：默认人群、前置知识和用户指定读者的调整方式。
- 讲清楚的方法：该领域适合的知识顺序、推导或证据表达、类比边界。
- 术语与易混概念：实际有区分价值的对象和检查问题，不只列缩写。
- 按主题审校：定义、证据、方法、假设、单位或测量口径、人群或工况、结论范围。
- 补充边界：可以补充的知识与必须有来源的特定事实。
- 可靠来源：推荐来源类型及核查条件；实际使用的来源注明版本、日期和依据，不伪造引用。
- 领域交付检查：能够在讲义、图文和短平台逐项执行的检查。

## illustration-guidance.md

包含适合画图的专业关系、图形类型与用途、符号和箭头含义、常见错误、不可虚构的数据及实际看图检查。用具体领域对象编写，不复制别的领域的图示问题。图示服务知识，不默认要求特定风格或图数。

## writing-examples.md

提供短而明确的领域例子：

- 第一作者正文的合格表达与应避免的转述。
- 一个完整的插图候选块，含位置、内容、目的、类型和边界。
- 知乎深入解释、公众号连贯叙述、CSDN 专业方法的方向及短平台的适用表达，不作为固定文章模板；五个平台沿用同一专业事实与证据边界、共同主题与单张总封面，两个短平台围绕同一精选图组分别表达，不自动拆为不同子主题。
- 应避免的夸张、跨层级推广或缺条件结论。

示例来源于可确定的知识或明确假设情境，不虚构亲历、样品数据、实验成绩、疗效或账号身份。短平台格式仍遵守通用平台参考，不在本文件重定义输出格式。
