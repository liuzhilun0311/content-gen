# 发布主题与封面

在完整正文审校后、配图审核稿生成前读取。封面与内容图一并规划、确认、生成和审校，不在平台稿完成后临时追加收费图片。

## 先定主题与图组

先依据完整正文确定一个共同发布主题，五个平台均围绕该主题展开。知乎、公众号保留完整知识链；抖音、小红书共用一组精选内容图及其顺序，分别调整措辞和表达节奏，不主动拆成不同子主题。先选择约3～6张互补内容候选，形成问题、机制或方法、条件、结论的知识链，再围绕该组分别组织文案，不先写极短文案再只配一张图。这是规划目标，不是平台限制或硬性数量；不得凑无关图。材料不足时说明实际范围和数量。封面不计入内容图数量。

短平台可以比长文章简洁，但文案和精选图组须共同概括总主题的核心知识链，不能只讲一个细节却套总主题封面。用户明确要求独立子主题或系列时另行规划范围和封面，不把默认单主题任务自动拆分。

## 封面表达

讲义或文章标题是主题来源，不必逐字照搬长标题。主标题用简短、明确的知识主题或可回答的问题；必要时副标题补足范围。可以保留完整讲义标题作副标题，不能靠夸张效果、虚构身份或未经支持的承诺吸引注意。

封面包含主标题、可选副标题和能呈现核心对象或关系的画面。用少量要素体现主题，不堆课程目录、长段落或全部公式，不增加无信息量的制作说明。不得以封面画面冒充正文未提供的结果证据。

沿用本任务参数表解析并校验后的比例、质量、清晰度、风格和配色，包括有效的展示默认；不写死参数，不在封面阶段用 `extend.md` 覆盖本任务快照。主标题与核心对象放在中央安全区域，外围留白；不得承诺一张图能无损适应各平台所有封面裁切。用户要求专用尺寸时在审核方案说明并确认，不静默为五个平台增加五套图片。

默认只生成一张总主题封面，五个平台复制同一原始资产，主标题、副标题和核心画面一致，不另生成平台专用封面。只有用户明确要求独立子主题或系列时才提出额外封面，并按范围确认；不靠裁剪或程序改字伪装成新主题封面。

封面候选记录 `role=cover`，实际 Type 仍选内容适合的现有类型，不新增 API 参数。提示词执行图中文字白名单和排版规则：标题、副标题、必要文字用双引号，其他描述不能渲染成文字。

## 审核与授权

在配图审核稿开头增加共同发布主题与单张封面规划：五个平台用途、两个短平台共用的内容图编号与顺序、主副标题、画面、Type × Style × Palette、比例和边界。候选内容图仍位于实际正文段落旁。

分别统计内容图、去重后的封面、总资产数和预计请求数。一个封面被五个平台引用只计一次生成请求，复制不计生图。允许用户修改主题、标题、画面和分组，修改后沿原审核流程确认，封面没有隐含生图授权。

按 [workflow-switches.md](workflow-switches.md) 应用审核模式：1时优先用允许的内置工具确认本版方案，包括共同主题、总封面与图组；0（默认）时记录同一方案、实际图数和请求范围，告知后直接执行。1模式下用户编辑稿件后重新读取并确认，0模式不追加审核问题。全部平台关闭或只要正文配图时不强制发布封面；关闭的短平台不编排单独发布素材。

起点3处理已有方案中的封面和共同主题；起点4执行确定方案生成封面和图组，两者生图前按方案审核开关处理。封面同样由技能自主检查文字、构图、专业内容及主题对应关系并有限修正复检；图片审核1时封面与内容图一起交给用户确认，0时直接进入正文插图和发布生成。起点5使用已有封面及图片，不重新生图，仍核对质量和所需图组确认。旧任务保留原模式与范围；仅做正文配图或关闭全部平台时不强制发布封面。

## 文件与交付

共享总主题封面用 `imgs/00-cover-main.<实际扩展名>`，稳定编号用 `cover-main`，不重排已有内容图编号。每个发布文件夹放同一张合格封面，复制时保留原文件名，因此封面按文件名排序在内容图前。仅在用户明确要求子主题或系列时使用额外 `00-cover-<主题标识>`。

五个平台分别保存到 `publish/知乎/`、`publish/微信公众号/`、`publish/CSDN/`、`publish/抖音/`、`publish/小红书/`。长文章 Markdown 仅作内部草稿，保存到 `_work/drafts/`，核对真实图片路径；按 [publishing-documents.md](publishing-documents.md) 为知乎交付内嵌图片的 DOCX，为公众号交付标题、简介、标签、正文分别复制的 HTML，为 CSDN 交付标题、正文、文章摘要分别复制的 HTML，各目录复制实际引用原图。短平台 Markdown 仍只含标题、文案、标签，不嵌图，封面与精选内容图直接放在同目录。需要打包长文章时同时包含引用图片并验证链接，不默认复制未引用的整套内容图，不重新生图。

来源映射写入内部 `imgs/platform-image-selection.json`，每个平台记录发布主题、封面来源与副本、正文路径、内容图来源及顺序；封面 `role=cover`，与内容图分开统计。副本与原图哈希一致，不将该工作记录放入公开正文。

完成前查看总封面，检查字形、标题范围、核心画面与五个平台内容一致；五个封面副本的哈希须相同。两个短平台内容图文件名集合、顺序和哈希也须一致，文案分别核对共同图组。错误封面不能进入发布包，不以正文迁就错误。缺失或不合格时说明受影响交付，保留合格正文和内容图，不宣称完整封面包完成。
