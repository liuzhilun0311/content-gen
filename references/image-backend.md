# 生图工具调用与任务衔接

content-gen 负责决定画什么、保存提示词、审核方案、专业检查、有限技术修正及插图。实际 API 请求、认证、下载、请求重试和图片信息摘要交给所选工具，本技能不包含生图 API 执行程序。

## 是否使用 image-gen

唯一选择为参数表中的“是否使用 image-gen”：1 使用（默认），0 不使用。不设自定义 API 配置项，不学习此开关。历史表缺行时记录默认1及来源。`config/.env` 只配置本地导出工具路径，不读取、迁移或覆盖其中遗留的生图凭据；调用时使用 image-gen 自己的服务配置。

- **1 使用**：发现并读取实际安装的 `$image-gen` 的 `SKILL.md`，使用该技能提供的渠道，不让用户在此分支填写其他渠道。没有安装时说明缺少依赖，保留方案与提示词；不静默换工具或按猜测路径执行。相邻开发目录只能在实际存在且用户当前任务明确使用该目录时采用，不能写死 `F:\skills_create` 或某位用户的安装路径。
- **0 不使用**：不读取、不检查、不安装、不调用 image-gen，不要求配置它，也不推荐其渠道。用户已有技能、程序或 API 时按明确要求执行，先读取实际用法和能力；没有指定可执行方式时交付方案及逐图完整提示词，等待用户提供图片或指定工具，不自行选择收费服务。该等待不是整个内容任务完成。
- 起点5或本次只做内容、方案时不调用生图工具。选择0不关闭方案审核、图片审核、图数预算约束或专业自检，不改变后续插图和发布流程。

## 参数与设计归属

按 [parameter-rules.md](parameter-rules.md) 解析任务快照，编号还原为语义值。明确选择优先，选填空白采用已展示兼容默认并记录来源；不得在调用时用后端默认覆盖当前任务。风格、配色、类型、语言、比例、参考用途、水印、密度、变体、批量、数量限制和保存方式仍由 content-gen 管理。

模型、清晰度、质量、背景 API 值、输出格式、压缩、服务审核和图片信息展示的固定选项仅在使用 image-gen 时适用。选择0时保留原表但标记这些字段不适用，不要求用户满足 image-gen 的模型清单、参考图16张/10MB或参考图单候选限制。其他工具的实际能力根据其文档核对，用户明确的格式、尺寸、透明背景等要求仍记录并执行，不能因表内字段不适用而丢弃需求。

审核稿和 `imgs/settings.md` 保留服务选择、设计参数、实际图数、变体、请求范围、预算和文件映射。选用外部方式时将其非敏感执行设置、能力及来源记录在工作资料，不创建第二张用户参数表，不保存 API 密钥。

## image-gen 的自然语言映射

以下仅适用于使用 image-gen，且不能覆盖当前明确答案或已展示的默认：

- “2.5”未指定版本时推荐 flare；“更精细、细节拉满、慢一点没关系”推荐 sunburst；旧模型仅在明确选择时使用。准确 ID 为 `gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`、`gpt-image-2`。
- “高清、更清晰”推荐2K；“4K、超清、大图、适合打印”推荐4K；不因技术图擅自升级。
- 横向场景推荐16:9，竖向海报推荐9:16或3:4；逐图比例写进方案，不因平台额外生成图组。
- “超高”映射 `xhigh`，“最高、极致画质”映射 `max`；旧模型不支持这两项。
- “透明底、抠图、无背景”对应透明背景与PNG/WebP；旧模型或JPEG冲突须先解决，不暗中换配置。
- “显示图片信息、带上参数”对应开启 `show_info`；“不显示图片信息、只要图片”对应关闭。摘要包含模型、实际分辨率、请求比例、已保存张数、质量、输出格式、背景设置、总耗时和输入/输出 token。

风格、配色、水印和知识内容写进完整提示词，不添加虚构的 API 字段。具体支持范围、认证、JSON/multipart、文件校验、下载和图片信息摘要由 image-gen 的说明与程序维护。

## 调用 image-gen

先读取 image-gen 自身说明，遵守其本机配置与首次使用规则。程序只读取 image-gen 自己的私有配置，不复制 content-gen 旧凭据，不把真实配置作为模型上下文，不把密钥传入提示词或命令行。缺配置时保留当前成果，按 image-gen 的说明引导本机配置。

在已发现的 image-gen 技能根目录解析 `scripts/gpt-image2.mjs` 的绝对路径；工作目录保持用户的工作目录。运行 `--check-config` 只检查非敏感配置，不发请求、不验证余额或服务可达性。

用本技能 `scripts/effective_image_config.py` 将已校验任务参数映射到 `_work/execution-config.json`。快照生成器保留在 content-gen；读取快照并执行请求的能力在 image-gen。绑定快照与提示词哈希到plan阶段证据，逐图比例按方案解析。

```powershell
$prompt = Get-Content -LiteralPath '<本任务提示词绝对路径>' -Raw -Encoding UTF8
node '<已发现的image-gen根目录>\scripts\gpt-image2.mjs' --execution-config '<本任务execution-config.json绝对路径>' --prompt $prompt --out-dir '<本图实际输出目录>' --dry-run
```

先离线核对请求，正式执行去掉 `--dry-run`，不把离线结果说成生成成功。有实际参考图时逐个添加 `--image '<实际参考文件>'`。不得另用矛盾CLI参数覆盖快照。读取以 `CONTENT` 开始的完整最终提示词，不临时简化。

每张选用插图对应独立提示词任务，变体数显式来自快照。按已选批量和宿主能力调度，不把不同提示词合并成变体；调度、正常请求数和每图最多一次技术修正范围仍由 content-gen 控制。

## 结果交接与复检

image-gen 的 `result` 包含 `status`、`images`、`metadata_path`、`errors`、`warnings`，图片路径取 `images[i].path`；使用真实绝对路径及实际后缀，不假定PNG。其他方式也须取得真实图片文件及编号映射，不能把提示词、下载URL或成功消息当作图片。

保留成功文件与原始生成记录，将提示词哈希、执行配置哈希、请求时间、状态、实际路径及方案编号绑定到工作资料。下载失败可恢复已有图片时先恢复，不重新请求生图。pending、部分成功或未知收费状态都不能宣称全部完成。

检查返回的尺寸、模型、格式与当前任务是否相符。随后由 content-gen 按 [illustration-workflow.md](illustration-workflow.md) 逐图实际查看，核对文字白名单、技术关系、构图及正文位置；生成器的文件检查不能替代专业自检。同方案有限修正仍由 content-gen 判断、保存修订提示词，再调用所选工具，不把决定权移给生成器。

余额、超时、5xx、下载失败或不明确计费状态不得外层自动重发生图。image-gen 内部有界429重试不授权内容流程再次重试；外部工具也须核对其失败与计费语义。实际费用只从生成工具可核对的结果读取，未知注明“暂未查到”，不复制管理凭据、不估价。

自检和适用的用户图片审核通过后，按原流程插图、导出及生成平台稿；不合格图不得进入成品。
