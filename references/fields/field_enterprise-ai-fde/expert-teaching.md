# 企业 AI 落地与 FDE：专业讲授规范

## 范围与读者

用于企业 AI 的需求发现、客户筛选、售前验证、现场交付、采纳、价值衡量、产品化沉淀和商业协作。围绕业务结果、工程实现与组织条件讲解，不把 FDE（Forward Deployed Engineer，前线部署工程师）等同于售前、外包、客户成功或单纯模型研发；具体职责以组织和材料定义为准。

默认面向了解基础软件概念、希望理解企业 AI 落地的创业者、产品经理及工程师。解释必要缩写和业务概念，不假设读者已有销售或采购经验。材料不足时不扩展成法律意见、合规认证结论或特定客户的投资与定价建议。

## 教学主线

以业务问题和可检验结果组织知识：为什么选择这个客户、如何认识其实际环境、如何验证价值、如何推动使用、怎样在交付中沉淀可复用能力。将执行方法与成立条件一起讲清，保留失败路径与退出机制。

- 灯塔价值、学习价值、合同收入与交付成本分别分析，不将知名客户等同于一定适合。
- 主张驻场时解释需要现场观察或协同的任务；远程也可能建立信任，不写“只有见面才有信任”等绝对判断。
- 方法建议是可采用的做法，不写成所有公司必须遵守的行业定律。
- 通用工具、人工服务和产品能力分别表达；说明试点中的人工投入，不将它假装成已实现的自动化。

## 术语与易混概念

| 概念 | 审校问题 |
|---|---|
| ICP、灯塔客户、内部支持者 | 客户画像是否明确？案例是否具有代表性？内部支持者有何资源、责任与影响力？ |
| PoC、试点、生产部署 | 验证目标、周期、验收条件及后续决策是否区分？演示通过是否被误当成生产可用？ |
| 采购方、预算方、使用者、否决方 | 是否区分角色及实际决策权限，避免只找单一高管？ |
| 数据质量、可信度与访问授权 | 用户信任的数据仍需质量及权限检查，不能因“实际在用”绕过正式授权 |
| 流程、组织、系统及利益关系 | 工作流程和组织影响不是模型能力；不推断具体个人的心理动机 |
| 效率、质量、收入、利润和 ROI | 指标口径、基线、成本范围和归因是否明确？速度提升是否误等同于收入或产能提升？ |
| 可复用能力与定制服务 | 哪些部分能复用？维护和迁移成本是否计入？不同客户是否真的具有共同需求？ |

## 分主题审校

- 客户筛选：写明业务负责人、数据可用性、资源投入、重复需求和背书许可。公开案例、客户商标及数据使用需要真实许可；不假定成交自动授权宣传。
- 尽调：分别检查数据、流程、组织、系统及利益影响。把纸面流程与实际观察区分，使用未验证资料时不推断客户内部事实。
- 价值验证：明确基线、样本、时间窗、测量方法、质量指标与业务结果；示例数字标为假设。速度改善不直接推出团队产能、利润或裁员幅度。
- 提案和 PoC：区分目标、已测结果及合同承诺，说明客户配合、里程碑、验收、停止条件和范围外工作；不把示例目标写成已达成效果。
- 产能及经济性：工作量、人日、周期、并行、毛利与机会成本分别计算。特定合同金额门槛、团队配置和并行项目数不是通用常数。
- 采购、安全及法务：解释审查问题和所需材料，不编造认证、访问权限、数据存储位置或合同效力。具体义务按适用地区、协议和最新官方文件核查。
- 内容和生态：区分营销观点、技术能力、伙伴关系和已公开交易事实；不承诺内容带来确定转化率或加入渠道即可免审查。
- 混合交付和出海：按任务、语言、时区、法规和客户资源解释边界，不对某地区的客户、契约精神或付费能力做无证据泛化。

## 来源与补充边界

推荐核查类型：企业正式公告、客户公开案例、产品或协议官方文档、原始演讲及访谈、可复查的研究与评估资料。此列表是来源建议，不表示已经阅读具体文件。

特定公司、人员、日期、引语、交易、用户数量、项目成绩和最新产品能力必须回到实际来源。官方案例也要保留自报口径；案例相关性不能证明产品必然造成结果。附录引用要读取实际附录及相应来源，不能只写“见附录”后假装完成核验。

可以补齐一般定义、步骤之间的逻辑、指标解释和明确标为假设的教学例子；不可补造客户经历、财务数据、测试结果或历史事件。事实冲突不能解决时在会话中澄清，不在公开正文添加待核实标记或纠错附录。

## 交付检查

检查定义、角色、阶段、基线、结果性质、证据范围和退出机制。讲义保留完整知识链；配图不将策略判断画成实证定律；四个平台对共同事实和条件保持一致。直接讲解，不冒充参与过客户交付的第一手当事人。
