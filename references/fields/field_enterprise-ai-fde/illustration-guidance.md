# 企业 AI 落地与 FDE：配图与看图规则

## 视觉关系

| 知识关系 | 适合的视觉结构 | 需要保留的条件 |
|---|---|---|
| 客户筛选 | 条件清单、决策流程 | 业务负责人、授权数据、合作投入及可复用需求 |
| 灯塔价值与学习价值 | 二维矩阵 | 坐标是分析维度，不是实测排名；无数据不画具体公司位置 |
| 从理解问题到验证和交付 | 阶段流程 | 决策点、客户配合、退出与回流路径 |
| 数据、流程、组织、系统、利益影响 | 五维尽调框架 | 五个不同对象；利益影响不等于猜测个人动机 |
| 交付到公开案例与推荐 | 关系链或框架 | 效果证据、传播许可；不是确定的转化因果链 |
| 提案的业务结果、验证、方法、风险 | 四层框架 | 目标与已测结果区分，避免用箭头暗示风险消失 |
| PoC 通过、修改或退出 | 分支流程 | 明确验收及停止条件，不把所有路径都画成签约 |
| 驻场与远程安排 | 任务对比图 | 按任务条件比较，不用好坏颜色暗示唯一模式 |
| 团队产能与排期 | 资源示意或待填模板 | 无真实数据不虚构时间、合同额、人员和收益 |

## 图形语义

箭头区分执行顺序、信息流、责任、依赖及反馈。循环只表示设计中的学习回流，不保证正向收益。颜色用于同一类角色或信息，不赋予未经测量的风险等级。

矩阵横纵轴写清名称和定性尺度。示意坐标不是调查数据，不配置真实公司散点。费用、时间及转化曲线须有实际数据；没有数据改用关系图或明确的假设案例。

默认 `3:4` 时优先将宽流程拆成上下阶段，不能挤小文字或裁切条件。确需更改比例时在方案中说明并确认，不能静默覆盖已选参数。共享图组服务四个平台，不为平台数量增加独立图套。

## 实际看图检查

- 核对主体角色、职责、阶段边界、箭头方向及退出分支。
- 分清“目标”“假设示例”“已验证结果”，图片不能将提案数字变成案例成绩。
- 保留数据授权、安全审查及用户采纳条件，不暗示能绕过审批或无限制接入数据。
- 审视流程是否把采购、法务和安全全部推迟到上线后；它们可以按任务并行介入。
- 术语、缩写和标签要可读，矩阵有坐标说明，图例与颜色含义一致。
- 不虚构客户商标、证言、认证标志、财务报表、内部架构或对话。
- 图片解释不能超出实际可见内容，不通过改写正确正文掩盖图中错误。
