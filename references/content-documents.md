# 完整配图正文阅读版

先执行 [article-layout.md](article-layout.md)。阅读版内部标题统一为任务名称，封面紧跟正文标题，图注末尾不留句号；原配图MD的文件名保留，导出文件只用任务名称。

阶段C的`<任务名称>_内容_配图.md`审校通过后，若“是否输出content”为1，读取本文件并导出三种格式。共同输入和原图保持，不通过平台稿改写、不缩成摘要、不重新生图。独立开关、历史兼容与处理范围见 [workflow-switches.md](workflow-switches.md)。

## 目录与文件

```text
publish/
  content/
    <任务名称>/
      <任务名称>.html
      <任务名称>.epub
      <任务名称>.pdf
```

content与五个平台目录同级，子目录为任务名称，不增加篇幅版本或时间后缀。原MD保留在任务根目录；阅读版图片内嵌，不额外复制整套原图。关闭时不创建目录或成品，不删除历史成果。开启时三份均为必需交付，缺一份不能宣称该输出已完成。

## 阅读与排版

- 目录依据实际标题层级生成，允许中文、重复标题和跳级标题；每个标题采用唯一稳定锚点，不能仅按标题文字生成ID。无章节时至少提供文章标题入口，不编造章节。
- HTML为离线阅读页，宽屏左侧目录、窄屏可折叠目录，点击跳转到正文。内嵌图片，正文不混入平台简介、标签、复制工具栏或制作说明。
- EPUB使用EPUB3容器，包含导航目录、正文阅读顺序、标题和语言元数据、样式及内嵌图片。目录和正文链接真实可解析，不依赖本地绝对路径或外部图片。PNG/JPEG保留原字节；WebP在书内无损转PNG，核对尺寸、透明度与解码像素，原WebP不变并记录转换。不得把转换副本称为原字节一致。
- PDF为A4阅读版，带可点击目录、章节书签和页码，目录页与正文分开。嵌入中文字体，避免乱码、横向溢出、图片裁切与图注孤页，表格和代码保持可读。PDF渲染器可能重编码图片，核对图义、比例和实际版面，不承诺图片压缩字节与原图一致。
- 图片默认居中、桌面正文宽度85%、手机100%，图注按“图1 图片含义”居中、常规字体、深灰且略小于正文；沿用 [publishing-documents.md](publishing-documents.md) 的图序和封面规则。纸面和电子书按可用宽度等比排图，尽量保持图片和图注同页。
- 完整保留正文、必要链接、标题、列表、表格、引用、代码及上下标。当前渲染器拒绝任意布局HTML和未核验LaTeX，先保留原稿并处理等价排版，不默默删内容。

## 执行

先记录有效full/publish参数及当前图组自检/适用确认。只输出content时关闭五个平台；本任务起点5可直接使用已有正文和图片。`scope=content`指仅基础正文阶段，不代表导出阅读版。

使用`scripts/export-content-documents.py`，复用现有Markdown排版程序，以Playwright Chromium打印PDF；依赖Python的python-docx、lxml、Pillow、pypdf及Node的marked、Playwright。解析当前环境实际路径，有依赖加载器时使用其返回值；优先已安装的Edge/Chromium，无需登录或生图密钥。

```text
python scripts/export-content-documents.py --source <任务根目录/任务名称_内容_配图.md> --task-name <任务名称> --task-root <任务根目录> --node <Node路径> --marked <marked入口路径> --playwright <Playwright的index.mjs路径> --browser <Edge或Chromium可执行文件>
```

输出目录由任务名称固定推导，不增加用户必填参数。脚本校验开关、任务名称、配图正文路径、已审校图组和当前确认；关闭时返回skipped，不创建文件。旧状态没有content路径时采用固定路径，不能借此扩大旧开关。导出前检查所有目标重名，只有用户授权局部修订时使用`--replace`，保留必要内部历史。先在临时目录完成三份并核验，再写发布目录；错误或依赖缺失时报告具体缺口，原稿保留。

轻量记录保存到`_work/export/content.json`，包含原MD哈希、原图顺序与哈希、三份输出哈希、标题锚点及格式检查结果。WebP转换另记像素核验。工作报告、截图、内部草稿不放content成品目录。

原配图MD含LaTeX或历史图注时，保留原件，在`_work/drafts/content/`另存已核验的等价排版副本。公式逐项检查运算、上下标、括号、符号及条件，图注编号和图片引用路径单独记录，不改其他正文。可追加`--render-source <副本MD> --transformation-record <替换记录JSON>`；两份都必须在本任务_work内。记录含原件source_sha256、reviewed:true及replacements数组，各项含before、after、count。脚本逐项重放并检查副本只含已审校替换；这证明变更范围和文本对应关系，不代替数学审校。导出报告和publish证据同时绑定副本与替换记录。

## 验收

1. 核对原配图MD未改、HTML正文与既有渲染结果一致、EPUB正文与HTML一致、PDF可提取完整正文；原图顺序、HTML图片原字节和EPUB原字节或核验转换一致。
2. 实际检查桌面和手机HTML的目录跳转、图片加载、居中图注及横向溢出；检查重复标题跳转各自位置。
3. 检查EPUB容器、manifest、spine、导航与图片资源，目录链接有效；有兼容阅读器时实际打开。不能将ZIP/XML检查称为所有阅读器兼容测试。
4. 实际渲染PDF目录页及正文页，核对中文、图注、分页、表格与代码；点击目录和书签，核对目的页及页码。没有渲染能力时明确版面验收缺口。
5. publish阶段证据同时绑定三份文件、原配图MD、`_work/export/content.json`及实际QA记录。`verify_task.py`按开关要求三份，并重查当前源文件、正文、目录和资源；关闭时不列入交付清单。最后运行任务完成验收，不把文件存在等同于版面正确。
